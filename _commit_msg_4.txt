第4批：统计模块与前端全量重写

后端统计模块：
- 修正「活跃用户」指标口径：改用 last_used_at（真实访问行为）统计，
  原实现用 expires_at（Token 是否过期），指标含义完全错误
  顺带修复了 last_used_at 只改内存不提交导致永远是 NULL 的 bug
- 用 CASE WHEN 做条件聚合，一次查询算出多个指标（而非发多条 SQL）
- 7 天趋势用 GROUP BY 一次查完（原实现循环 7 天发 7 条 SQL），缺失日期补 0
- 设备状态分布补齐缺失状态，避免前端饼图缺块
- 新增聚合接口 /statistics/dashboard：首页从 5 个请求降为 2 个
- 统计接口按角色分级：个人数据登录可见，全局数据仅管理员

前端全量重写：
- 请求层 http.js：拦截器统一处理带 Token、解包 data、错误提示、401 跳登录
  含「错误提示防重复」和「401 跳转防重复」两处细节处理
- 组合式函数 usePagination：消除 7 个列表页的重复分页代码，筛选条件自动联动
- 设计令牌 tokens.css：所有颜色/间距/圆角集中定义，深色模式只改变量不改组件
  Element Plus 主题变量也指向自定义令牌，保证样式统一
- 登录状态用 reactive + 函数而非 Pinia（全局状态只有用户一项，按需引入复杂度）
- 菜单由路由表自动生成，不会出现「页面存在但菜单没有」
- 路由守卫声明式鉴权（meta.requiresAdmin），并明确前端守卫不是安全边界
- EquipmentImage 组件作为图片展示的唯一出口，彻底解决原项目
  「一个字段三种解析方式」的问题
- ECharts 按需引入 + 实例销毁 + resize 处理 + 主题跟随
- 构建优化：manualChunks 手动分包 + 路由级懒加载
- 主题初始化在挂载前执行，避免深色模式 FOUC
